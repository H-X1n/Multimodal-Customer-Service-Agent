# 架构说明

## 目标

构建一个架构清晰、可扩展的多模态客服智能体，围绕“多模态理解 / RAG / 对话管理”三大模块组织。

## 模块划分

### 1. 多模态理解模块

文件：

- `agent/multimodal/understanding.py`

职责：

- 接收文本问题与图片路径
- 识别用户主意图与子意图
- 判断是否需要检索知识库
- 为后续对话管理输出结构化问题计划

当前实现：

- 基于规则和输入结构做轻量分析
- 预留接入视觉模型和多模态微调模型的扩展点

### 2. RAG 模块

文件：

- `rag/vector_store.py`
- `rag/knowledge_service.py`
- `utils/file_handler.py`

职责：

- 解析产品手册与手册插图
- 建立向量索引
- 根据用户问题召回文本片段
- 从片段中解析相关图片 ID，并映射到实际图片路径

当前实现：

- Chroma 持久化向量库
- 文本 chunk 切分
- 图片 ID 解析与配图回传

### 3. 对话管理模块

文件：

- `agent/dialogue/manager.py`

职责：

- 维护会话上下文
- 重写追问类问题
- 将一次提问中的多个问题拆开
- 为每个问题确定类别和检索需求

### 4. 智能体编排模块

文件：

- `agent/services/customer_support_agent.py`

职责：

- 串联理解、检索、生成三段流程
- 组织 grounded prompt
- 统一输出最终回答、证据和图片引用
- 兜底处理模型异常，减少失败率

## 幻觉抑制设计

- 回答必须依赖 `KnowledgeService` 返回的证据
- 证据不足时显式返回“当前知识库未提供足够依据”
- 问题逐项拆解，避免多个问题混答
- 检索证据与图片路径随响应一起返回，便于前端展示和人工复核

## 多模态微调扩展建议

后续可新增 `training/` 模块，接入：

- 多模态指令微调数据
- 产品故障图像 + 问答对
- 客服历史多轮对话数据

推荐训练目标：

- 意图识别
- 多问题拆解
- 图片故障定位
- grounded response generation
